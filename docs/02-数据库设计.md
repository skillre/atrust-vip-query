# 数据库设计文档

## 一、数据库选型

### 1.1 选型说明

| 数据库 | 适用场景 | 本项目选择 |
|--------|---------|-----------|
| SQLite | 轻量级、嵌入式、单机部署 | ✅ **MVP阶段** |
| MySQL | 生产环境、多用户并发 | 后续升级选项 |
| PostgreSQL | 复杂查询、大数据量 | 后续升级选项 |

### 1.2 SQLite 优势

- **零配置**：Python 内置，无需安装
- **单文件**：整个数据库就是一个 `.db` 文件
- **轻量级**：适合 MVP 快速验证
- **易迁移**：后续可平滑迁移到 MySQL/PostgreSQL

### 2.2 users 表（用户信息表）

#### 表结构

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | INTEGER | PRIMARY KEY, AUTOINCREMENT | 主键 |
| user_name | TEXT | UNIQUE, NOT NULL | 用户名（登录名） |
| display_name | TEXT | | 显示名（中文名） |
| phone | TEXT | | 手机号 |
| email | TEXT | | 邮箱 |
| directory_name | TEXT | | 用户目录（本地/LDAP等） |
| group_path | TEXT | | 组织架构路径 |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 更新时间 |

#### SQL 建表语句

```sql
CREATE TABLE IF NOT EXISTS users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_name TEXT UNIQUE NOT NULL,
    display_name TEXT,
    phone TEXT,
    email TEXT,
    directory_name TEXT,
    group_path TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 索引
CREATE INDEX IF NOT EXISTS idx_users_display_name ON users(display_name);
CREATE INDEX IF NOT EXISTS idx_users_phone ON users(phone);
CREATE INDEX IF NOT EXISTS idx_users_directory ON users(directory_name);
```

#### 数据来源

| 字段 | Syslog 来源 | API 来源 |
|------|------------|---------|
| user_name | actor.name | name |
| display_name | actor.displayName | displayName |
| phone | actor.phoneNumber | phone |
| email | actor.email | email |
| directory_name | actor.directoryName | userDirectoryName |
| group_path | actor.groupPath | groupPath |

### 2.3 vip_records 表（虚拟IP记录表）

#### 表结构

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | INTEGER | PRIMARY KEY, AUTOINCREMENT | 主键 |
| user_name | TEXT | NOT NULL | 用户名（外键） |
| virtual_ip | TEXT | NOT NULL | 虚拟IP地址 |
| real_ip | TEXT | | 用户真实IP |
| event_type | TEXT | | 事件类型 |
| timestamp | DATETIME | NOT NULL | 记录时间 |
| created_at | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |

#### SQL 建表语句

```sql
CREATE TABLE IF NOT EXISTS vip_records (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_name TEXT NOT NULL,
    virtual_ip TEXT NOT NULL,
    real_ip TEXT,
    event_type TEXT,
    timestamp DATETIME NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_name) REFERENCES users(user_name)
);

-- 索引（关键查询路径）
CREATE INDEX IF NOT EXISTS idx_vip_user_name ON vip_records(user_name);
CREATE INDEX IF NOT EXISTS idx_vip_virtual_ip ON vip_records(virtual_ip);
CREATE INDEX IF NOT EXISTS idx_vip_timestamp ON vip_records(timestamp);
CREATE INDEX IF NOT EXISTS idx_vip_event_type ON vip_records(event_type);
```

#### event_type 取值

| 值 | 说明 | 数据来源 |
|----|------|---------|
| online_query | 在线用户查询 | aTrust API |
| syslog_access | 访问日志记录 | Syslog |
| syslog_vip_apply | 虚拟IP申请 | Syslog |
| syslog_vip_revoke | 虚拟IP释放 | Syslog |

## 四、数据保留策略

### 4.1 清理规则

| 表 | 保留时长 | 清理方式 |
|----|---------|---------|
| users | 永久 | 不清理 |
| vip_records | 90天 | 定时清理过期记录 |

### 4.2 清理SQL

```sql
-- 清理90天前的虚拟IP记录
DELETE FROM vip_records 
WHERE timestamp < datetime('now', '-90 days');
```

### 4.3 定时任务

```python
# 每天凌晨2点执行清理
import schedule
import time

def cleanup_old_records():
    db.execute("""
        DELETE FROM vip_records 
        WHERE timestamp < datetime('now', '-90 days')
    """)

schedule.every().day.at("02:00").do(cleanup_old_records)
```

## 五、数据查询示例

### 5.1 查询用户最新虚拟IP

```sql
SELECT u.display_name, v.virtual_ip, v.timestamp
FROM users u
JOIN vip_records v ON u.user_name = v.user_name
WHERE u.user_name = 'zhangsan'
ORDER BY v.timestamp DESC
LIMIT 1;
```

### 5.2 按虚拟IP反查用户

```sql
SELECT u.display_name, u.user_name, v.timestamp
FROM users u
JOIN vip_records v ON u.user_name = v.user_name
WHERE v.virtual_ip = '10.10.10.100'
ORDER BY v.timestamp DESC
LIMIT 10;
```

### 5.3 查询历史记录

```sql
SELECT virtual_ip, real_ip, event_type, timestamp
FROM vip_records
WHERE user_name = 'zhangsan'
  AND timestamp >= datetime('now', '-7 days')
ORDER BY timestamp DESC;
```

## 七、性能优化

### 7.1 索引优化

已创建的索引覆盖主要查询场景：
- `idx_vip_user_name`：按用户查询
- `idx_vip_virtual_ip`：按IP反查
- `idx_vip_timestamp`：按时间范围查询

### 7.2 查询优化

- 使用 `LIMIT` 限制返回条数
- 避免 `SELECT *`，只查询需要的字段
- 大量查询时考虑分页

### 7.3 数据量预估

| 场景 | 100用户 | 1000用户 | 10000用户 |
|------|---------|----------|-----------|
| 每日新增记录 | ~500条 | ~5000条 | ~50000条 |
| 90天总量 | ~45000条 | ~450000条 | ~4500000条 |
| 数据库大小 | ~5MB | ~50MB | ~500MB |

SQLite 可以轻松应对以上数据量。
